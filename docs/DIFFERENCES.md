# Differences from the Next.js version

The aim was a carbon copy. These are the places where it is not, and why.

## Deliberately not ported

| Next.js version | Here | Why |
|---|---|---|
| Client portal (`/account/*`: client sign-in, requests, shipments, notification settings) | **Left out** | It was switched off and unlinked in the Next.js site ("clients don't need to log in"). When clients should request shipments themselves, build it on the same `clients` and `shipments` tables and the `Notify` service. |
| Emailed 6-digit code sign-in for staff | Left out | Staff sign in with username + password. A forgotten password is reset by a super admin. The temporary-password flow replaces what the code login was used for. |
| Vercel Analytics and Speed Insights | Left out | Vercel-specific. Add Google Analytics or a similar script to `resources/views/layouts/app.blade.php` if wanted. |
| `/api/health` keep-alive and the daily Vercel cron | Not needed | These existed to stop the free Supabase project pausing. MySQL on the hosting account does not pause. |
| Supabase row-level security | Server-side checks | The Laravel controllers and middleware decide who may do what (`EnsureStaff`, `EnsureAdmin`), and the database is never exposed to the browser. |
| `scripts/telegram-webhook.mjs` | Staff → Telegram page | The same one-click set-up. |

## Different underneath, same on screen

| Next.js | Laravel |
|---|---|
| React components, `next/image`, `next/font` | Blade components, `<img srcset>` of resized WebP files (`npm run photos`), self-hosted fonts via `@fontsource-variable` |
| Server actions with `useActionState` | Normal form posts, enhanced by `resources/js/forms.js`: the server answers with the re-rendered form, which is swapped in place and gets focus. Without JavaScript the page simply reloads with the same result. |
| Supabase auth and database | Laravel session auth and MySQL/SQLite (`users`, `clients`, `shipments`, `shipment_events`, `notification_log`, `telegram_link_tokens`) |
| Resend HTTP API | Laravel Mail over SMTP (works with Resend, Brevo, or the host's mail server) |
| The contact/quote forms posted to `FORM_WEBHOOK_URL` only | Same, and when no webhook is set they are emailed to the business address if mail is configured; otherwise the page offers a pre-filled email, as before |
| Tracking numbers `TD-YYMM-XXXXXX` made by a database function | Made by `App\Support\TrackingNumber` (same alphabet, Bhutan month stamp) |
| Staff accounts in Supabase Auth | `users` table; usernames map to `<username>@staff.td-global.invalid` (never delivered) |
| IDs of form fields generated by React (`useId`) | Fixed IDs (`contact-name`, ...) |

## How "the same" was checked

- The stylesheet is the original `globals.css` (both sites use Tailwind 4), and every component's class list was ported unchanged.
- `tools/compare.py` compares each page's markup (tags, classes, attributes, text) with the live Next.js site: 95–99% identical, and what remains is generated IDs and the extra wrappers the scripts need.
- Element-by-element geometry (position and size of every link, button, heading, paragraph, image and input) was measured in a real browser on the original and the clone for `/`, `/about`, `/blog`, `/calculator`, `/clearing-agent-gelephu`, `/contact`, `/pricing`, `/quote`, `/services` and `/services/import-clearance`: **no element differs by more than 1px**. That check found and fixed two real differences (whitespace inside flex rows, date format).
- Animations and behaviour (header menus, collapsible search, hero carousel with its stop/start control and 6-second autoplay, service and article carousels, scroll reveal, certificate viewer, calculator, forms with error summaries and focus handling, password show/hide) were exercised in a browser.
